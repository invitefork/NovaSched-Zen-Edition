## 安装失败

截图中的四个属性分别是 `ro.soc.model=O3`、`ro.soc.manufacturer=XRing`、`ro.board.platform=xring_o3_asic` 和 `ro.hardware=xring_o3_asic`。2.7.1 只接受完整的 Xring O3 名称，没有组合厂商和型号，也漏掉了平台别名，所以在第三步硬件检测时退出。

本版接受上述组合与精确的平台别名。单独的 `O3`、其他厂商和互相冲突的处理器证据仍会拒绝，CPU 簇和频率范围也照常校验。这不是放开所有未知设备安装。

安装失败日志会保存在 `/data/adb/novasched/install-last.log`。处理器检测、配置初始化和二进制自检失败时，即使管理器清理安装目录，日志仍可用于排查。没有提供 ARCH 的管理器改用 Android 的 ABI 属性，支持 arm64、arm64-v8a 和 aarch64 的环境标记。

## 三星开机卡死与重启

没有三星机型、固件版本、pstore 或上一轮内核日志，无法确定“显示壁纸后卡死”是哪个具体驱动或服务触发。源码能确认两个启动风险：服务只等待开机完成，没有等待首次解锁；厂商覆盖频率上限后，模块会频繁且无次数限制地重写。

本版按以下方式降低这两个风险：

- 自动启动等待当前用户首次解锁，再连续等待 30 秒。每次等待都检查管理器停用和卸载标记。直接执行 start、restart、daemon 也会检查启动和解锁状态。
- 检测到三星厂商属性或 One UI 属性时，在运行内存中强制使用保守配置。四档仅设置 CPU 频率范围，保留每个 CPU policy 的原厂调速器，不捕获、不写入或恢复 scaling_governor；暂停 NovaFAS、fas-rs 跟随、uclamp、输入加速、CPUSet、热插拔、调速器参数、CFS 参数、GPU 控制、性能服务停用及节点看门狗。旧的自定义配置也会受到同样约束，原配置文件保留。
- 三星不自动重申被系统改回的频率上限，也不自动重试失败的策略写入；WebUI 保留降级状态与日志，用户可以手动切档后再试。
- 其他设备的上限重申最多三次，间隔至少十秒；普通策略下发失败最多自动尝试三次，之后暂停自动重试。较低的系统频率上限照常接受。失败事务的待重写队列会清除，避免回滚后再次写入。
- 未确认频率上限时，NovaFAS 不继续动态加压。启动和配置重载时，FAS 线程使用实际适配后的配置，避免界面显示关闭但线程仍运行。

启动保护会在第一批调度写入之前保存本轮 boot ID。调度与心跳连续稳定三分钟后，记录才标为稳定。若这个阶段发生异常重启，下一次启动会写入管理器的 disable 标记并停止再次下发，防止反复执行同一批启动控制。正常停止且节点恢复完成时会记录正常结束。

这项保护只能覆盖“稳定确认之前的异常重启”，不能证明重启由模块导致，也不能代替管理器安全模式。确认记录损坏或无法保存时，不执行调度写入。因保护停用后，先保留日志，确认原因和版本，再从管理器显式重新启用；重新启用允许一次新的观察期。

## 骁龙和 WALT

WALT 是内核的负载跟踪实现；一些 Qualcomm 内核还提供名称为 walt 的 CPUFreq 调速器。用户态模块不能给不支持它的内核添加 WALT，切换调速器也不等于替换整个调度器。

默认 auto 保留正在使用的原厂动态调速器。原厂使用 walt 就保留 walt，使用 schedutil 就保留 schedutil。只有原厂处于固定 performance / powersave，或请求的调速器不在可用列表时，才在内核实际提供的调速器中回退：walt、schedutil、interactive、ondemand、conservative。手动请求一个实际可用的调速器仍然生效；三星保守策略优先保留原厂值。

不能凭调速器名字保证更省电或更高帧率。要比较 WALT 和 schedutil，应固定游戏、亮度、温度与功耗限制，在同一内核上比较帧时间、功耗和发热。CPUFreq 节点定义见 [Linux 内核文档](https://docs.kernel.org/admin-guide/pm/cpufreq.html)。

## 使用与反馈

请安装完整 `NovaSched-v2.7.2-release.zip`，完成后重启，并首次解锁等待 30 秒。源码包与单独 WebUI 更新包都不能修复旧核心的安装和启动逻辑。覆盖安装保留档位、应用规则与有效自定义参数，配置代际保持 370。

现有循环重启设备应先通过管理器安全模式或设备可用的恢复方式停用旧模块，再更新。本版沿用已支持的九款处理器；未增加 Exynos 处理器支持。

如仍有问题，请提供机型、One UI / Android 版本、处理器、root 管理器版本，以及这些记录：

- 安装问题：`/data/adb/novasched/install-last.log`。
- 启动问题：模块目录的 `boot-entry.log`，运行目录的 `novasched.log`、`bootstrap.log`、`boot-guard` 和 `last_error`。
- 系统异常重启：`/sys/fs/pstore` 中的上一轮内核记录（若内核保留），或设备提供的 last_kmsg。重启后尽早保留，避免后续启动覆盖。

可以在 root 终端执行：

```sh
su -c '/data/adb/modules/NovaSched_Zen_Edition/bin/novasched diagnose'
```

最终本地验证见 `docs/validation-v2.7.2.txt`。模拟管理器、模拟内核节点和界面检查都不能代替三星真机的连续启动、功耗与帧率测试。
