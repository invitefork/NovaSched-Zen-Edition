# v2.6.1 修复与使用说明

作者：ZenJooo

## 交付范围

`source.zip` 是完整可编辑源码；`webui-update.zip` 是现有模块的界面更新。两者没有 Android ELF，不能作为完整模块刷入。本次没有生成 `release.zip`，也没有连接手机。

解压 WebUI 更新包后，用 root 终端执行 `sh /实际路径/scripts/install-webui.sh`。可在参数中指定已安装模块目录，例如 APatch 的 `/data/adb/ap/modules/NovaSched_Zen_Edition`。脚本只更新 WebUI，不更改 `module.prop` 版本、用户配置或守护进程。失败时恢复旧界面。

完整更新：解压源码，准备 Rust、Android ARM64 标准库和 NDK r27d，运行 `bash scripts/build.sh`；安装生成的 `dist/NovaSched-v2.6.1-release.zip` 后重启。

## 问题与处理

| 问题 | 根因与处理 |
|---|---|
| 上下白条 | 原界面未启用宿主边缘显示，也未读取宿主安全区。新代码探测 `enableEdgeToEdge` / `enableInsets`，兼容宿主 CSS 安全区与浏览器 `env()` |
| DPI、旋转和键盘 | 以 CSS 像素布局；安全区不再二次乘 DPI。用 `visualViewport` 处理可视高度变化，旧宿主用窗口高度回退 |
| 手指带动整个 UI | 整个文档滚动，加上 `window.scrollY` 动态裁切。改为固定屏幕外壳与内部纵向滚动，页面返回时恢复内部滚动位置 |
| 底部按钮不响应 | `pointerdown` 就由导航容器捕获事件。超过拖动阈值才捕获，普通轻触留给原按钮 |
| 弹窗关闭仍不可点 | 关闭动画与历史返回交错，inert 锁可能保留。历史关闭立即释放，整个导航容器与后台个性化面板正确管理锁定 |
| 前台应用入口重复弹窗 | 子按钮点击继续冒泡到父卡片。父卡片过滤子按钮，键盘入口同样处理 |
| FAS 开启后仍未检测到 | 仅启动时检查。改为持续检查，区分接口有效、进程存在、接口不可读、内容无效和未检测到 |
| FAS 档位切换失败 | 旧写法适用于 sysfs，却没有截断 FAS 的普通文件。写 `fast` 会留下之前较长模式的尾部。新写法不创建节点，只截断已有普通文件并读回；可修复残留错误模式 |
| UI 版本错位 | 新 UI 与旧二进制混用且旧服务版本覆盖页面版本。分别显示界面与服务版本，打包检查全部元数据 |
| 节点未生效却显示成功 | 频率上限排队重试但仍发布 ready。现在携带待确认数量，原子发布实际模式与健康状态；未读回时不显示操作成功 |
| 触控加速持续耗电 | 日常应用使用短脉冲；只打开具有触屏能力的输入设备，排除传感器，空闲时不重复读写 uclamp |
| 可选节点与最高档回退 | 支持传统 cpuctl 与两种统一 cgroup 路径；不可用时跳过。显式无限制 CPU 上限使用硬件最大值，自动 governor 避免固定频率模式 |

CSS 能铺满宿主允许的 WebView 窗口。旧管理器若没有边缘显示接口，系统栏外的原生留白仍由宿主控制，需要更新管理器或使用支持此接口的独立 WebUI 宿主。DOM 模拟测试不能证明所有机型的原生留白已经消失。

## 四档默认上限

以下是每个模板活跃 CPU 簇的顺序，**不是整颗处理器的功耗百分比**。数值相对该簇检测到的物理最大频率；实际按 OPP 表对齐。均衡使用中间频率范围，尚未通过各设备的能效曲线测定真实甜点。

| 处理器模板 | 省电 | 均衡 | 性能 | 极速 |
|---|---|---|---|---|
| DIMENSITY8350 | 62% / 54% / 50% | 84% / 78% / 74% | 94% / 92% / 92% | 100% / 100% / 100% |
| DIMENSITY9400PLUS | 58% / 52% / 48% | 82% / 76% / 74% | 94% / 92% / 92% | 100% / 100% / 100% |
| SM8450 | 62% / 50% / 48% | 82% / 74% / 72% | 92% / 90% / 90% | 100% / 100% / 100% |
| SM8475 | 60% / 50% / 48% | 84% / 76% / 74% | 94% / 92% / 92% | 100% / 100% / 100% |
| SM8550 | 60% / 50% / 50% | 84% / 78% / 76% | 95% / 92% / 92% | 100% / 100% / 100% |
| SM8650 | 58% / 50% / 48% / 50% | 82% / 76% / 74% / 76% | 94% / 92% / 90% / 94% | 100% / 100% / 100% / 100% |
| SM8750 | 58% / 50% | 78% / 72% | 92% / 92% | 100% / 100% |
| SM8850 | 58% / 50% | 78% / 72% | 92% / 92% | 100% / 100% |
| XRING_O3 | 60% / 54% / 48% | 82% / 78% / 74% | 94% / 92% / 92% | 100% / 100% / 100% |

省电和均衡不常驻抬高 CPU 最低频率；性能采用 10% 最低频率目标；极速开放频率范围并允许空闲回落。所有默认模板保留在线 CPU，不强制修改 cpuset，不关闭系统服务或 GPU 温控。

| 档位 | 触控利用率脉冲 | 持续时间 | 后台利用率上限 |
|---|---|---|---|
| 省电 | 15% | 100 ms | 65% |
| 均衡 | 20% | 140 ms | 85% |
| 性能 | 28% | 180 ms | 恢复捕获的原值 |
| 极速 | 40% | 220 ms | 恢复捕获的原值 |

脉冲不会降低更高的原始利用率下限，并受 top-app 的利用率上限约束。缺少可用触屏输入或 uclamp 节点时保持频率策略，不借助不断执行 shell 命令实现加速。旧自定义输入策略没有 `modes` 时沿用其原有脉冲配置。

极致省电与任何刷新率下的完全流畅不能仅靠源码保证。屏幕、GPU、基带、温度、固件和后台任务都会影响体验。本次提供可回退的默认策略，具体收益需真机对比。

## 检查状态

已执行的检查结果保存在 `docs/validation-v2.6.1.txt`：WebUI 静态检查、模拟交互与宿主桥、渲染缓存、36 组配置约束、安装入口、界面更新回滚和软件 GPU 着色器检查。

未执行：Rust 编译与原生回归、Android ARM64 ELF 构建、浏览器截图、各 DPI 的真实 WebView 测试、实际电池功耗和游戏帧率。原因是环境没有 Rust / NDK / Chromium，且没有连接测试手机。附带的原生测试涵盖 FAS 晚启动、重建、16 个模式转换、失效文件修复、外部调度暂停、cgroup 路径、四档脉冲、最高上限和 governor 回退；需要在有 Rust 的主机运行后确认。

`bash scripts/validate.sh` 在缺少 cargo 时会明确输出 NOT RUN；不能把之前版本的原生测试记录当作本版通过结果。`scripts/build.sh` 必须通过原生测试和 ELF 检查后才复制二进制并打包。

## 手机验证顺序

1. 完整编译安装后重启，检查 UI 和服务版本均为 v2.6.1。
2. 在五个页面验证纵向滚动、边缘拖动、导航轻触、返回、输入框键盘和横竖屏；改变显示大小后重新检查。
3. 服务启动后再打开 Scene FAS，观察 10 秒内检测状态变化；切换四档，检查模式接口读回。FAS 的文件缓存刷新由它自身决定，读回成功不代表某个游戏已被 FAS 接管。
4. 每档使用相同亮度、刷新率、应用和测试时长，观察信息流帧率、CPU/GPU、温度和电量。极速检查进入和离开重载后的回落。
5. 验证应用规则、Scene 联动、其它调度器接管、停用和卸载恢复。后台音频和常用通知应在省电、均衡档一起检查。

完整服务支持只读命令 `fas-diagnose`、`scene-diagnose` 和 `game-diagnose`。运行诊断包含实际节点、策略目标与 FAS 状态，可用于调整某台手机的配置。
