# WebUI 性能与布局修正

作者：ZenJooo。日期：2026-10-13。调度核心版本仍为 v2.2.8 / 328。

## 布局

反馈截图中的加号比导航高，是因为旧版在导航容器之外给加号设置了 `bottom:24px`。现在导航和加号位于同一条 54px 高的 flex 行，中间留 8px；整个容器距离底部为 `8px + safe-area-inset-bottom`。窄屏按可用宽度收缩导航，设置页隐藏加号并居中导航。

固定日期顶栏和滚动卡片曾同时显示在同一区域。现在主内容的上裁切边界随页面滚动同步，固定在顶栏下边缘；二级页按 58px 标题栏裁切，设置页使用自己的页面布局。浮层采样中的卡片和文字遵循相同的顶栏边界。

## 绘制

- 每个玻璃表面缓存背景版本、实际材质、圆角、位置和尺寸。上述内容不变时跳过 WebGL 绘制与位图复制；改卡片透明度只重画相关卡片。
- 导航滑块使用父导航的背景版本，移动时复用纹理。弹窗与个性化面板移动时复用已经记录的底层文字；浮层自己的文字变化不触发底层文字重新测量。记录文字时跳过屏幕外文本。
- WebGL 绘制缓冲按需扩容，并从正确的底部视口区域复制，不再按每个控件的尺寸来回重建。模糊暂存画布也复用。
- 相同采样域和模糊值复用纹理对象；背景像素变化时使用 `texSubImage2D` 更新，尺寸改变时才重新分配存储。LRU 缓存最多 12 项，且总纹理内存不超过 24 MiB。
- 背景纹理最多采样 60 万像素，减少上传和模糊成本。最终表面沿用原有 DPR 与 120 万像素的视口预算，DOM 文字保持宿主分辨率；背景采样分辨率降低可能使透镜内的背景细节稍柔和。
- 页面不可见时停止帧调度，离开视口的玻璃表面释放位图。重复设置相同选项不再触发绘制。上下文恢复后重新建立纹理与表面。

透镜和色散 GLSL 公式没有变动；这仍是原有 WebGL 适配器。

## 验证

已执行：

| 命令 | 结果 |
| --- | --- |
| `npm run test:webui` | 20 项静态检查与六组服务交互场景通过 |
| `npm run test:performance` | 静态缓存、滑块与浮层移动、材质更新、纹理内存、前后台和上下文恢复通过 |
| `npm run test:shader` | 实际 GLSL 编译链接、四组 AGSL 公式比对、大缓冲视口裁切通过 |
| `python3 scripts/test-webui-updater.py` | 更新、旧界面备份、错误模块拒绝及失败回滚通过 |

在合成的 393 × 852px、DPR 2 环境中，统计首次绘制及随后请求的 720ms 静止窗口：

| 调用计数 | 修正前 | 修正后 |
| --- | ---: | ---: |
| WebGL 绘制 | 552 | 12 |
| 绘制画布宽高写入 | 1012 | 2 |
| 纹理上传 | 5 | 5 |

这些数字来自 Canvas/WebGL 模拟宿主，用于检测重复调用，不代表手机 FPS、耗电或真实耗时。实际着色器另由 Mesa llvmpipe 执行，比对最大通道误差约 0.294 / 255。原始输出在同目录 `webui-performance-*-results.txt` 中。

`scripts/verify-ui-render.cjs` 增加了 320、393、768px 下加号与导航上下边缘、间距、视口边界、设置页隐藏状态及滚动裁切检查。可在有 Chromium 的主机上设置 `CHROME` 后运行 `npm run test:render`。本环境未执行该浏览器检查，也未连接 Android 设备，因此没有真机截图或性能测量。

## 更新

源码 ZIP 内含 `scripts/install-webui.sh`。将解压后的完整文件夹放到已安装 v2.2.8 模块的设备，在 root 终端运行该脚本，再关闭并重新打开 WebUI。脚本只替换界面并备份旧界面，原生守护、调度配置和应用规则继续使用已有文件。
