## 第五步与安装等待

用户截图能确认第五步 Scene 检查没有显示结果和第六步；未提供该设备的阶段日志，无法仅凭截图断言是系统查询阻塞、进程中断还是管理器提前结束。

检查确认旧脚本没有对整个 Scene 步骤设置截止时间，等待提示还使用后台 shell 和信号陷阱。新版用独立原生任务管理检查子进程，保留每个阶段的原始输出并写入明确的结束记录。shell 读取结束记录，避免只看管道末端的成功状态；没有记录、多行损坏记录和信号退出均不能当作通过。

| 检查步骤 | 总时限 |
|---|---:|
| 核心自检 | 20 秒 |
| 硬件探测 | 20 秒 |
| 配置初始化 | 30 秒 |
| 自动偏好初始化 | 10 秒 |
| Scene 当前用户查询 | 10 秒 |

Scene 是可选联动，失败或超时会报告检测失败并继续第六步；必需步骤失败会停止安装。超时检查放在独立进程组，终止时连同其查询子进程一起结束。等待提示每三秒显示实际任务、已等待时间和轮换短对话。控制台只保留关键信息，完整适配结果留在日志，安装末尾明确显示“六站全部结束”。

回归实际启动 Scene 检查并故意等待三十秒，验证十秒截止时间、生效的 `124` 结束记录和第六步完成提示；也覆盖错误返回、SIGTERM、缺失/损坏记录。bash 与 dash 的 `set -eu` 环境均完成相应安装场景。原生进程树测试验证超时后的子孙进程不能继续写入延迟标记。

## 卸载与残留

流程先设置卸载标记，禁止重新启动、旧 Scene 回调和配置/凭据写入，再取得控制锁并停止守护与监督。无法正常退出的守护只允许在身份和 pidfd 核验后结束；确认运行锁释放后才恢复快照与清理，仍持锁时保留恢复资料并报错。

恢复节点值、权限、属性和服务后，逐个检查 Scene JSON 和脚本归属。有有效原回调备份时恢复原字节和权限；备份本身是 NovaSched 早期残片时直接移除，避免卸载后重新留下自己的回调。缺失接管标记、半套回调或损坏备份也会继续处理其它可清理项目。其它调度器替换的文件保留；脚本必须有完整的归属注释，文本中碰巧提到 NovaSched 不足以认定归属。

清理整个运行目录，包括配置、应用规则、自动分类、退役偏好、会话凭据、节点/Scene 备份、查询临时文件、启动状态、锁和内部日志；同时处理安装记录、外部日志目录及待更新副本。卸载输出直接显示，不再写入会残留的 `uninstall.log`。开机入口日志放在模块目录，并随模块移除，迟到的开机 shell 不创建运行目录。

共享存储在开机早期可能仍处于凭据加密状态，此时会生成唯一命名的一次性清理脚本。解锁后移除对应用户的日志并自删；每次最多等待十五分钟，未解锁则退出进程并保留下一次开机重试入口。重新安装后取消旧任务；多用户设备需相应用户解锁。测试验证解锁前不能误报清理完成、解锁后自删、重新安装后的新日志保留、用户及 Android 目录链接不被递归跟随。

## 真实设备限制

未进行物理 Android 设备刷入或卸载测试；bash / dash 回归不能等同于 Magisk、KernelSU、APatch 所用 BusyBox ash 的实机验证。没有测量实际帧率、温度、功耗与调度切换延迟。截图中的 Snapdragon 8 Gen 3 / SM8650 / houji 识别结果仍按现有配置处理，未臆造该设备的额外频率数据。

建议在该设备检查：安装正常完成第六步；Scene 未安装、已安装与查询失败的显示；游戏到日用切档；覆盖升级保留偏好；管理器卸载并重启解锁后运行目录和外部日志消失；重新安装不被旧清理任务影响。
